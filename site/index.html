Architecture

How Upheld Works in 3 Steps

Deterministic claim-receipt reconciliation designed specifically for autonomous agent loops.

01

Ingest Telemetry

Captures structured transcripts: tool call arguments, stdout/stderr streams, process exit codes, and file mutation payloads from agent execution envelopes.

// Ingests session transcript
transcript: { tool_calls: [...], output: [...] }
02

Correlate Claims

Extracts semantic assertions from the agent's prose response and maps each assertion directly to its mandatory concrete evidence requirement.

// Maps claim to evidence rule
"fixed bug" ➔ requires: git_diff + test_run
03

Verify & Report

Evaluates whether each claim holds up against the empirical evidence. Outputs a structured audit manifest (Report mode by default; exits non-zero in --strict).

// Verdict breakdown
upheld: 8 | refuted: 1 | unsubstantiated: 0
Verification Rules

Strict Evidence Standards by Claim Type

Passive assumptions do not count as proof. Every claim type enforces concrete verification rules.

file_written Write Event

Verifies the agent actually performed a file write or edit operation. Mere existence on disk is rejected as insufficient proof.

Required Evidence: Tool call payload or disk delta record with nonzero mutated bytes.
command_run Process Receipt

Validates that claimed terminal commands were executed within the current session runtime with timestamps and process records.

Required Evidence: Recorded execution envelope with command string and spawned PID.
test_passed Zero Exit + Suite Pass

Requires an exit code of 0 together with parsed test-runner summary counters. Masks and swallowed errors (|| true) are flagged.

Required Evidence: Exit code 0 + non-empty test suite stdout proving execution.
diff_applied Tree Mutation

Verifies that the file tree or target buffer changed according to the claimed patch or refactor specification.

Required Evidence: Git staging delta or AST transformation verification.
lint_clean Static Analysis

Validates claims like "no lint errors remain" against actual linter runs and zero-diagnostic outputs.

Required Evidence: Linter CLI invocation record with clean diagnostic buffer.
benchmark_hit Telemetry Proof

Checks quantitative performance claims ("improved throughput 3x") against captured benchmark logs.

Required Evidence: Benchmark run execution log with recorded numeric baseline comparison.

Capabilities

Built for Real Engineering Pipelines

Zero cloud lock-in, deterministic verification, and transparent reporting.

Local-First & Private

Runs 100% locally on your workstation or CI runner. No transcripts, code, or telemetry are ever uploaded to third-party clouds.

Report Mode Default

Generates clear, informative audit logs without blocking iteration. Review discrepancies when you need them.

Optional --strict CI Gate

Enable --strict in GitHub Actions or pre-commit hooks to fail the build whenever an unsubstantiated or refuted claim is detected.

Agent Agnostic

Supports standardized transcript formats from Claude Code, Cursor, MCP-compatible agents, and custom autonomous LLM loops.

Write-Evidence Semantics

file_written checks for genuine write operations and mutation receipts rather than trusting passive file existence.

Deterministic Engine

No LLM-as-a-judge unpredictability. Verification rules use pure structural logic, diff analysis, and execution receipts.

Getting Started

Local Build & Quickstart

Clone the repository and build from source. No global npm packages or closed services.

Open source & locally built: Upheld is not published to the global npm registry (do not run npm i -g upheld). Clone and build directly from source.
bash — Clone & Build Locally sh 
# 1. Clone the repository
git clone https://github.com/chuofringer/upheld.git
cd upheld

# 2. Build the verification binary
cargo build --release

# 3. Verify an agent transcript in default (Report) mode
./target/release/upheld verify --transcript ./session.json

# 4. Optional: Run with --strict to fail CI on unverified claims
./target/release/upheld verify --strict --transcript ./session.json

Honesty & Transparency

Frequently Asked Questions

Direct answers on architecture, deployment, and evidence rules.

Q: Is Upheld a hosted SaaS platform?

No. Upheld is an open-source, local-first CLI tool and verification library. There are no hosted cloud dashboards, tracking beacons, or account logins.

Q: Is there a global npm package?

No. Upheld is not published to npm under a global name. Run it by cloning the GitHub repository and building from source locally.

Q: How does file_written differ from file existence?

A file simply being present on disk does not prove the agent modified or created it during the session. file_written requires direct evidence of a write tool call or file mutation event during that specific session.

Q: What is Report mode vs. --strict mode?

By default, Upheld runs in Report mode, outputting a clear diagnostic table and JSON manifest without terminating your workflow.

When passed --strict, Upheld exits with a non-zero code if any claim is refuted or unsubstantiated, suitable for CI gate enforcement.

Q: Does Upheld use an LLM to evaluate claims?

No. Upheld avoids non-deterministic LLM-as-a-judge scoring. Verification is computed via structural log analysis, exit code checks, AST diffs, and cryptographic hash comparisons.

Q: Who builds Upheld?

Upheld is an independent vibemapper project created to establish reliable ground truth for autonomous agent engineering workflows.
