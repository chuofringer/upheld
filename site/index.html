Architecture

How Upheld Works in 3 Steps

Deterministic claim-receipt reconciliation designed specifically for autonomous agent loops.

01

Ingest Claims Document

Accepts structured JSON claims (or stdin) declaring tests that passed and files written during the agent session.

// Ingests claims document
{ "claims": [{ "type": "tests_pass", "cmd": "npm test" }] }
02

Evaluate Ground Truth

Re-executes test commands to check exit codes/counts, and checks git status and file mtimes against --since for write evidence.

// Evaluates empirical evidence
re-run test cmd (exit 0) + git status / mtime
03

Verify & Report

Reconciles claims into upheld, unmet, and unclaimed verdicts. Outputs a report by default; exits non-zero under --strict.

// Verdict breakdown
upheld: 2 | unmet: 1 | unclaimed: 0
Verification Rules

Thin-Wedge Claim Types & Evidence Standards

Passive assumptions do not count as proof. Upheld focuses on exactly two thin-wedge claim types.

file_written Write Evidence

Verifies that a claimed file was actually modified or created during the session. Passive presence on disk without mutation is rejected as unmet.

Required Evidence: File exists and shows write evidence via git status (untracked/modified) or mtime newer than --since timestamp.
tests_pass Zero Exit Receipt

Verifies that the claimed test suite executes to completion with a successful exit code (0) and matches claimed test metrics if specified.

Required Evidence: Direct test runner execution receipt with exit code 0 and matching test counts (passed/failed/total).

Capabilities

Built for Real Engineering Pipelines

Zero cloud lock-in, deterministic verification, and transparent reporting.

Local-First & Private

Runs 100% locally on your workstation or CI runner via Node.js. No source code or evidence is ever uploaded to third-party clouds.

Report Mode Default

Generates clear, informative audit logs without blocking iteration. Review discrepancies when you need them.

Optional --strict CI Gate

Enable --strict in GitHub Actions or pre-commit hooks to fail the build whenever an unmet claim is detected.

Agent Agnostic

Accepts a structured JSON claims file from any producer, harness, hook, or autonomous agent loop.

Write-Evidence Semantics

file_written checks for genuine write operations via git status and mtime vs --since rather than trusting passive file existence.

Deterministic Engine

No LLM-as-a-judge unpredictability. Verification rules use deterministic git status inspection and process exit receipts.

Getting Started

Local Build & Quickstart

Clone the repository and build from source. No global npm packages or closed services.

Open source & locally built: Upheld is not published to the global npm registry (do not run npm i -g upheld). Clone and build directly from source.
bash — Clone & Build Locally sh 
# 1. Clone the repository
git clone https://github.com/chuofringer/upheld.git
cd upheld

# 2. Install dependencies & build TypeScript source
npm install && npm run build

# 3. Verify claims in default (Report) mode
node dist/bin.js verify path/to/claims.json

# 4. Optional: Run with --strict to fail CI on unmet claims
node dist/bin.js verify --strict path/to/claims.json

Honesty & Transparency

Frequently Asked Questions

Direct answers on architecture, deployment, and evidence rules.

Q: Is Upheld a hosted SaaS platform?

No. Upheld is an open-source, local-first CLI tool and verification library built with Node.js and TypeScript. There are no hosted cloud dashboards, tracking beacons, or account logins.

Q: Is there a global npm package?

No. Upheld is not published to npm under a global package name. Run it by cloning the GitHub repository, running npm install && npm run build, and invoking node dist/bin.js.

Q: How does file_written differ from file existence?

A file simply being present on disk does not prove the agent modified or created it during the session. file_written requires direct evidence via git status (untracked or modified) and/or file modification timestamp comparison against --since.

Q: What is Report mode vs. --strict mode?

By default, Upheld runs in Report mode, outputting a clear diagnostic table and JSON manifest without terminating your workflow (exits 0).

When passed --strict, Upheld exits with a non-zero code if any claim is unmet, suitable for CI gate enforcement.

Q: Does Upheld use an LLM to evaluate claims?

No. Upheld avoids non-deterministic LLM-as-a-judge scoring. Verification is computed via deterministic re-execution of test commands, git status inspection, and mtime comparison.

Q: Who builds Upheld?

Upheld is an independent vibemapper project created to establish reliable ground truth for autonomous agent engineering workflows.
